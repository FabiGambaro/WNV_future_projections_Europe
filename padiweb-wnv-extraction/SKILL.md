# PADI-web WNV case extraction (R)

Goal: from a PADI-web export, produce a table of **locally acquired human WNV infections in Europe at NUTS3 x year where the text states the place of infection** (grade A), plus a separate layer of cases the text explicitly calls local (autochthonous / locally acquired / domestic / had not travelled) but locates only by residence or reporting area (grade B), where every row can be checked against a verbatim quote from the article text. The table is built to favour precision: a presence that is missed is acceptable, an imported or non-local case counted as local is not (the table is combined with ECDC data).

All code is **R** (`readr`, `dplyr`, `stringr`, `stringi`, `tidyr`, `purrr`, `sf`, `writexl`, `httr2`, `jsonlite`, `xml2`). Check packages load before planning around them; install missing ones once. When the pipeline folder is available (`R/01_prepare.R` ... `R/05_outputs.R`, `data/`), run those scripts rather than rewriting them; otherwise implement the steps below exactly.

## What a replicating colleague needs
The whole package folder, not only this file: `R/`, `data/` (aliases, NUTS3 corrections, record corrections, added records and review decisions are part of the method), `tools/` (download, reader brief, quote check, batch merge). Plus the PADI-web articles CSV and location file, and the folder of original pages for masked articles (`ORIGINALS_DIR`). Set paths with environment variables (see `R/config.R`) and run R with `LANG=C.UTF-8`.

## How to run
- **In a Claude chat (no API key; small samples up to ~100 articles).** The R scripts and `data/` files are bundled in this skill's folder: copy the folder to a working directory and run the scripts from there (install R and the packages in the sandbox if missing). Run steps 01 and 02, read each sampled article yourself for step 3 and save the records as `records_extracted.csv` with the columns of `full_run/records_extracted.csv`, then run 04 and 05 with `RECORDS_CSV` pointing to that file.
- **Full corpus.** Either use `R/03_extract_claude_batch.R` with an `ANTHROPIC_API_KEY`, or (no API key, as done for `full_run/`) split the articles into batches of ~50 and have parallel reader agents in Claude Code each read one batch, following `tools/reader_brief.md`, writing `bNNN_records.jsonl` / `bNNN_outcomes.jsonl` and validating them with `python3 tools/check_quotes.py`. Merge the batches into `records_extracted.csv` and `article_outcomes.csv`, then run 04 and 05. The 2026 full run read 4,555 articles in 97 batches (18,600 records, all quotes verified); runs are interrupted by plan usage limits and resume where they stopped.

## 0. Inputs
- **Articles CSV = the main source.** One row per article: `id`, `title`, `text` (full text, machine-translated to English), `publication_date`, `url`, `country` (a PADI-web tag), language. Confirm column names first; print counts, date range and a few sample rows, never whole tables. `text` contains line breaks: read with `readr::read_csv`, never line by line.
- **PADI-web location file = fallback for coordinates only.** Use its lat/lon when an extracted place name matches a location in the same article. Never use it to decide which places are cases (it covers a minority of articles, its NUTS3 column is mostly empty, it has no infection/residence/hospital role, and it contains noise such as "West Nile" geocoded to Uganda).
- PADI-web's `country` tag (`source_country` in the outputs) is unreliable: it is neither the outlet's nor the case's country (a Romanian outlet reporting a case exposed in Milan is tagged IT). Never use it to locate or classify cases; places and countries come from the article text only.

## 1. Pre-filter (loose, case-insensitive, on `text`) and sample
```r
wnv_re   <- regex("West Nile|WNV|Nile fever|Nile virus", ignore_case = TRUE)
human_re <- regex("\\b(?:patients?|persons?|people|m[ae]n|wom[ae]n|humans?|hospitali[sz]ed|neuroinvasive|died|deaths?|cases? of (?:infection|disease))\\b", ignore_case = TRUE)
```
This only removes clearly off-topic articles; real selection happens in extraction. Report counts after each filter. Flag masked articles: text matching `-{3,}|\*{3,}`. For a small sample, either fix the article set with a file of ids, or `set.seed(42); slice_sample(keep, n = 100)` and record the seed.

## 2. Masked articles (before extraction)
Masking (`-----`, `*****`) can hide place names (and also person names or photo credits). For every masked article:
1. **Read the original article.** Masking appears to be PADI-web's person-name anonymisation, and it also hides place names that look like names (Dos Hermanas, Lebrija, Pella, Larissa, Serbian districts). Download the original pages once, on a computer that can reach the news sites: `Rscript tools/download_masked.R <list.csv> originals` (list = masked article ids and urls; Google News RSS links are base64-wrapped real URLs). Keep the saved pages as study data (never on GitHub) and pass the folder as `ORIGINALS_DIR`. Extract from the original text as well as the translation.
2. **If access is blocked or fails, flag the article** (`access = blocked`) and look for an **unmasked duplicate in the corpus**. Use a duplicate **only if its text is identical to the masked article outside the masked parts**: after normalising case, accents, punctuation and spacing, every unmasked stretch must match word for word, and each masked span may correspond to 0-12 words. A similar but different article (another translation, an edited version) must never fill the gaps; list such near duplicates (e.g. >= 50% word overlap) for information only.
3. **Otherwise fill masks from the PADI-web location file**: its `position` column is the character offset in the article text, and a location whose position falls inside a masked span is the hidden name (shown as `-----[Dos Hermanas]`; records get `text_source = padiweb+locations`).
4. If none of these works, extract from the masked PADI-web text, never guess hidden names, and list the article in `Masked_articles` with `url_original` for a manual check. Report how many masked articles were read through each route.

## 3. Extraction (each article read in full)
One record per place x case cluster. Skip animal cases, mosquito pools, surveillance/risk areas without human cases, country-only totals and general information. Fields:
- `place` (as written), `country` (ISO2 of the place), `place_level` (municipality / province / region / country; "province" = a unit that is itself NUTS3, including city-states such as Berlin, Hamburg and Vienna), `admin_hint` (province/county given for a municipality)
- `role`: infection (the text says the person was infected / contracted the disease there, at home or abroad) | residence | reporting_area | hospital | possible_exposure
- `status`: **autochthonous only when the text explicitly says so** ("autochthonous", "locally acquired", "local transmission", "domestic case", "indigenous", "acquired in <this country/area>", "had not travelled") | imported | not_stated. A stated place of infection without such wording is `not_stated` (its `role = infection` already records it, and it counts in step 7).
- `human_case` (yes / unclear), `certainty` (confirmed / suspected), `n_cases`
- `year_infection`, `year_basis`: explicit season/year | onset | diagnosis | publication
- `quote`: verbatim sentence(s) supporting the record; `note`; `text_source` (padiweb / original / duplicate:<id> / padiweb+locations)

Rules: residence is not place of infection ("a woman from Navarra infected in Utrera" -> Utrera, role infection). "Cases come from X" and "a case in the province of X ... infected locally" give residence/reporting area, not a place of infection. Keep hedged wording ("probably infected in X") as role infection with the hedge inside the quote: R grades it. When an article lists earlier travel cases by year ("in 2007 from Cyprus"), record each one. Leave `year_infection` empty when the text gives no year for that case. Two candidate exposure places -> one `possible_exposure` record each. Year defaults to publication year; flag articles published Nov-Feb and older bulletins re-published under a later date. Small sample: read interactively. Full corpus: the Claude API Message Batches endpoint with this schema as structured output (`R/03_extract_claude_batch.R`, prompt in `data/extraction_prompt.md`, model `claude-opus-5-5`; run `dry-run` first, API key from `ANTHROPIC_API_KEY`).

## 4. Verify quotes
`str_detect(source_text, fixed(quote))` for every record, against the text named in `text_source`; fix or drop non-matches and report the match rate.

## 5. Assign NUTS3 (2024 and 2021)
Reference layers: Eurostat GISCO NUTS3 polygons 1:1M (`NUTS_RG_01M_<year>_4326_LEVL_3.geojson` from gisco-services.ec.europa.eu; fall back to Eurostat Nuts2json 1:10M and flag that border points need checking), and GeoNames `cities1000`. Routes, in order (record which was used in `geo_method`):
1. **Name match**: the place is itself a NUTS3 unit. Normalise (`stri_trans_general(x, "Any-Latin; Latin-ASCII")`, lowercase, drop words like county/province/regional unit/oblast/regija/regiji) and match NUTS3 names within the place's country; Greek merged units match on either part; exonyms and press spellings come from `data/nuts3_aliases.csv` (Seville->ES618, Larissa->EL612, Bucharest->RO321, South Backa->RS123...). Greek script is transliterated with modern values first (β->v, η/υ->i, so Εύβοιας -> evvoias, not euboias). If there is still no match, inflected or hyphenated forms are compared by stem within the same country and accepted only when one unit matches (Πιερίας->Pieria, Južnobačkog / Juzno-backi->Južnobačka, Pomurski->Pomurska).
2. **Municipality**: GeoNames point (same country) or, failing that, the PADI-web location point -> point-in-polygon (points < 5 km outside a generalised coastline take the nearest polygon). If the text names the province (admin_hint, or "Place (Province)"), keep only points inside it. Ties: same NUTS2 as the article's other places, then largest population.
3. **Municipality not found -> province named in the text, always before marking it failed**: first the admin_hint or the province in brackets right after the place ("Villanueva del Rey (Córdoba)" -> ES613); else the only NUTS3 name of the same country in the same sentence as the place (flag these for review, since a sentence can also name a residence).
4. Countries with a single NUTS3 (Cyprus CY000, Luxembourg LU000) assign directly; cases the text places in Northern Cyprus are flagged for a keep/drop decision (mention it in `note`).
5. Region- or country-level only -> no NUTS3 (never a centroid), except a region that is itself a single NUTS3 unit (its NUTS2 has one NUTS3: Berlin DE300, Hamburg DE600, Wien AT130), which is matched by name. Unresolved -> `failed`.
Before geocoding, R appends `data/added_records.csv` (cases the readers missed) and applies `data/record_corrections.csv` (field fixes after review, each with its reason; a fix applies only when the record still has `old_value`, so it never silently overwrites a fresh extraction and unmatched fixes are printed). Apply `data/manual_corrections.csv` (NUTS3 fixes) last. NUTS 2021 codes come from the same point (or a point inside the 2024 polygon). Flag points within 1 km of another NUTS3 region (3 km with the 1:10M fallback). A whole country named as if it were a province ("AP Kosovo (one case)") is country level. The study area is continental Europe: records in other continents or in EU outermost regions (FRY*, ES70, PT20, PT30) are never explicit and go to Not_explicit (`in_study_area` in `R/04_geocode_grade.R`); Cyprus is kept.

## 6. Evidence grades
- **A**: place of infection stated without hedging (role infection)
- **B (hedged)**: place of infection given with hedged wording, checked in R (`hedged_re` in `R/04_geocode_grade.R`) on the quote: probably / most likely / likely / presumed / possibly / suspected / believed / allegedly / apparently / assumed / thought to have / may have contracted, and the same words in German, Italian, Spanish, French, Romanian, Slovene, Hungarian, Croatian, Serbian and Greek. Also records marked `infection_uncertain` in `data/record_corrections.csv` (Pančevo and Požarevac 2022, where the sentence may refer to mosquitoes). These count in the B layer, not the presence table (decision 2026-10-20).
- **B**: explicitly local, located by residence or reporting area. "Explicitly local" is checked in R (`literal_local` in `R/04_geocode_grade.R`): the reader marked `status = autochthonous` **and** the source text contains a literal term (autochthonous, locally acquired, domestic case/origin/transmission, or the same word in the original language) or an explicit statement that the person had not travelled. Paraphrases ("local mosquitoes", "no evidence that they resided abroad") do not count.
- **B-**: residence/reporting area, not explicitly local
- **C**: hospital location only, competing exposure places, suspected case, or unknown year
- **Human review**: `data/review_decisions.csv` holds the reviewer's final decision for records in the Review tab (matched on article_id + place + quote): A (place of infection confirmed), B (local but place of infection not explicit, e.g. a hospital or residence town with "had not travelled"), or exclude (unclear place or date of infection, suspected case). It overrides the automatic grade, and `review_reason` shows the decision and the reviewer's note; decided records leave the Review tab, so it lists only what still needs a check. Re-review whenever the Review tab changes; unmatched decisions are printed.
- plus `exclude: human case unclear`, `excluded by review`, `no NUTS3 (coarser level)`, `no NUTS3 (geocoding failed)`

## 7. Outputs (explicitly local records only)
- `NUTS3_year_presence_explicit.csv` and tab `NUTS3_year`: one row per NUTS3 x year where the text **states the place of infection** (grade A: role = infection, "contracted the disease in <town>", "exposed in Italy (Milan)", including travel cases infected in another country). Presence, not summed counts; the same events are reported many times. Columns: country (NUTS prefix, EL for Greece), nuts3_2024, nuts3_2021, nuts3_name, year_infection, n_articles, n_records, places_mentioned, article_ids.
- `NUTS3_year_B_residence.csv` and tab `B_residence`: sensitivity layer of NUTS3 x years supported only by grade B records: hedged places of infection ("probably infected in Hamburg"), and records that explicitly say the case was local with a literal term (autochthonous / locally acquired / domestic case, or the same word in the original language; or an explicit statement that the person had not travelled ("did not report travel in the last month"), the surveillance definition of a locally acquired case; paraphrases such as "local mosquitoes" or "no evidence that they resided abroad" do not count, and those records go to Not_explicit) but place it only by residence or reporting area ("domestic cases recorded in the Regional Unit of Pella"). NUTS3 x years already in the presence table are not repeated.
- `padiweb_wnv_explicit.xlsx` with tabs:
  - `README`: rules and counts of the run.
  - `NUTS3_year`: same as the presence CSV (grade A).
  - `B_residence`: same as the B CSV.
  - `Records`: every explicit record (grade A, or explicitly local per the rule above), whatever its NUTS3 result, one row per place x case cluster.
  - `Review`: explicit records that need a human look, with `review_reason`: grade C (hospital only, competing exposure places, suspected, unknown year), no NUTS3 code found, manual correction, province taken from the same sentence, point within 1 km of a NUTS3 border, Northern Cyprus, corrected year, published Nov-Feb (check year).
  - `Not_explicit`: all other records (no local wording, paraphrase only, imported), for traceability.
  - `Masked_articles`: one row per masked article: `url_original`, `access` (ok / blocked / failed), `http_status`, `duplicate_id` and `rule` (identical unmasked duplicate), `n_masks`, `n_filled` and `filled_names` (masks filled from the location file), `text_for_extraction` (original article / unmasked duplicate / PADI-web text with N of M masks filled / masked PADI-web text), `n_records`, `n_explicit_records`, `to_check`.
  - `Articles`: `article_id`, `outcome` (records found, or why none: no human case, animals only, general information...).
- Record columns (Records, Review, Not_explicit): `article_id`, `url` (clickable; Google News links decoded), `publication_date`, `source_country` (PADI-web tag, not used), `place`, `place_level`, `admin_hint`, `role`, `status` (wording in the text: autochthonous / imported / not_stated; records with a stated place of infection are often `not_stated`), `human_case`, `certainty`, `n_cases`, `year_infection`, `year_basis`, `nuts3_2024`, `nuts3_name`, `nuts3_2021`, `geo_method` (route used in step 5), `province_hint`, `lon`, `lat` (point used for point-in-polygon), `evidence_grade`, `quote` (verbatim), `quote_verified`, `text_source`, `note` (reader's comment), `review_reason`.
- Presence table columns (NUTS3_year, B_residence): `country` (NUTS prefix, EL = Greece), `nuts3_2024`, `nuts3_2021`, `nuts3_name`, `year_infection`, `n_articles`, `n_records`, `places_mentioned`, `article_ids`.
- Keep the R scripts and a short methods note with counts at each step, so colleagues can reproduce the run.
